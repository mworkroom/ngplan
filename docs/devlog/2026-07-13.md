# 2026-07-13 ngplan Development Log

회원 시작값 입력을 실제 사용자 입력 범위에 맞게 단순화하고, 수동 계획표의 가로 공간 사용을 줄였다. 반복 시뮬레이션을 위해 작업 자료가 브라우저를 닫아도 유지되도록 저장 방식도 강화했다.

- 화면에 이번 기간 PVP 목표, PVP 시작값, 좌 시작값, 우 시작값만 노출하도록 라벨과 회원 카드 요약을 정리했다.
- 수동 계획표 오른쪽 날짜 열의 sticky 동작을 제거하고 왼쪽 날짜 열에만 sticky를 유지했다.
- 날짜 열 너비를 148px에서 약 30%인 44px로 줄였다.
- 숫자 셀 최소 너비를 76px에서 57px로, 입력창 너비를 64px에서 48px로 줄여 기존의 75% 수준으로 조정했다.
- 작업 스냅샷 저장 위치를 탭 수명에 종속된 `sessionStorage`에서 브라우저 사이트 데이터인 `localStorage`로 전환했다.
- 기존 `sessionStorage`의 v2 또는 v1 작업 자료를 발견하면 검증·마이그레이션 후 `localStorage`로 자동 승격하고 기존 세션 사본을 제거하도록 했다.
- 작업 자료 초기화는 구형 데이터가 남지 않도록 두 저장소의 v1·v2 키를 모두 제거한다.
- 수동 계획표 회원 열을 루트 중심 대칭 순서로 변경했다. 왼쪽 가지는 root-first 순서를 뒤집어 바깥쪽부터 루트 방향으로 놓고, 오른쪽 가지는 root-first 순서 그대로 루트부터 바깥쪽으로 놓는다.
- 오른쪽 가지가 내부적으로 왼쪽 자식으로 꺾여 있어도 표지 번호가 `3 → 2 → 1 → 2 → 3`으로 보이는 회귀 테스트를 추가했다.
- 자동 계획 후보를 찾은 직후 기존 수동 계획표의 자격 경고가 함께 보여 후보 경고처럼 오해되는 문제를 확인했다. 후보가 아직 적용되지 않았음을 알리는 안내를 추가하고 `현재 계획 사용` 버튼을 `검증 계획 확인·적용`으로 바꿨다.
- 자동 계획 적용 통합 테스트에서 기존 `확인이 필요한 안내`가 사라지는지 확인하도록 회귀 검증을 보강했다.
- `localStorage` 전환 뒤 남아 있던 “현재 탭 임시 저장·탭을 닫으면 삭제” 문구를 브라우저 사이트 데이터 삭제 전까지 유지된다는 실제 동작에 맞게 수정했다.
- 관련 UI 테스트 33개를 실행해 통과를 확인했다.
- 영구 저장과 기존 세션 자료 승격을 포함한 저장·복원 테스트 21개를 실행해 통과를 확인했다.

## Decisions

- 계산 엔진과 저장 형식이 사용하는 내부 시작 장부 필드는 제거하지 않고 UI에서만 숨겼다. 기존 계산 계약과 저장 데이터 호환성을 유지하면서 사용자가 구분할 필요가 없는 값을 입력받지 않기 위해서다.
- 오른쪽 날짜 열은 긴 표의 끝에서 날짜를 확인하는 용도로 남기되, 가로 스크롤 중 화면을 차지하지 않도록 일반 열로 처리했다.
- 서버 계정 저장 없이 반복 테스트의 입력 부담을 줄이는 것이 목적이므로, 기존 스냅샷 계약은 유지하고 저장 매체만 `localStorage`로 바꿨다. 브라우저의 해당 사이트 데이터가 삭제되기 전까지 같은 브라우저에서 복원된다.
- 엄밀한 재귀 중위 순회는 오른쪽 가지가 왼쪽 자식으로 꺾일 때 루트 오른쪽이 `3 → 2`로 보일 수 있었다. 사용자가 원하는 것은 각 노드의 좌우 관계를 그대로 그리는 것보다 루트를 기준으로 깊이가 대칭으로 보이는 시트이므로 표시 순서를 별도 규칙으로 확정했다. 자동 계획의 root-first canonical 순서와 계산 순서는 변경하지 않았다.
- 검증된 자동 후보는 자격 미달 정산을 verifier가 거부하므로 “자격 확인 필요” 후보가 아니었다. 화면에 남아 있던 경고는 적용 전 기존 수동 입력의 결과였으며, 자동 덮어쓰기를 피하는 미리보기·확인 계약은 유지하되 두 상태의 차이를 명시하기로 했다.
