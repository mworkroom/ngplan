# 2026-07-26 개발 로그

## Work Summary — Phase 6A 클라우드 안전 저장 구현

Phase 4 자동 계획을 베타 동결한 상태에서 계산 알고리즘은 수정하지 않고, 브라우저 자료 유실을 줄이는 Phase 6A 저장 기능을 구현했다. 기존 엄마용 Supabase 프로젝트와 두 Auth 계정을 재사용하고, Supabase를 원본으로, IndexedDB를 오프라인 복구용 사본으로 사용한다.

## Work Completed

* `public.ngplan_projects`와 `public.ngplan_daily_backups` schema, 저장 revision·시각·사용자 trigger, 같은 transaction의 상파울루 날짜 하루 보관본 upsert를 migration으로 추가했다.
* 기존 `workspaces`·`workspace_members`에 별도 `ngplan` 작업공간과 두 기존 Auth 사용자의 동일 권한 membership을 추가했다.
* 두 저장 테이블에 RLS와 명시적 grant를 적용했다. 인증된 작업공간 구성원에게 SELECT·INSERT·UPDATE만 허용하고 익명 접근과 클라이언트 DELETE 권한·정책은 제공하지 않았다.
* `CloudPlanDocumentV1`에 프로젝트 설정 초안과 수동 계획 초안만 원격 원본으로 저장하도록 했다. 현재 화면, 확대 비율과 자동 계획 체크포인트는 IndexedDB에만 남긴다.
* IndexedDB 캐시를 사용자와 작업공간에 결합해, 이전에 온라인 membership을 확인한 계정만 해당 로컬 자료를 오프라인에서 열 수 있게 했다.
* 로컬 약 0.5초, 원격 약 2초 debounce, 단일 원격 in-flight 저장, 최신 대기본 후속 저장, 지수형 자동 재시도, 온라인 복귀와 수동 `다시 저장`을 구현했다.
* Google 로그인, 저장된 계획 목록, 새 계획, 숨김/복원, `저장 중`·`저장됨`·`오프라인 저장됨`·`저장 실패` 상태를 클라우드 진입 화면과 기존 편집기에 연결했다.
* 프로덕션 진입점은 기존 `localStorage` 자료를 이전하지 않고 Supabase 작업공간에서 새로 시작하도록 했다.
* GitHub Pages 빌드에 Supabase 공개 repository variable을 연결하고 CI에 격리된 Supabase DB 테스트 job을 추가했다.
* 운영 Supabase DB에 두 migration을 적용하고 프로젝트 URL과 publishable key를 로컬 개발 환경 및 GitHub repository variable에 연결했다. service role·secret key는 브라우저 구성에 사용하지 않았다.
* 공유 Supabase Auth에서 신규 가입을 차단하고 공개 설정의 `disable_signup=true`를 확인했다. 기존 Site URL과 다른 앱의 Redirect URL은 유지하면서 `https://mworkroom.github.io/ngplan/`만 허용 목록에 추가했다.

## Decisions

* 계획 업무 날짜는 서버 리전이나 접속 기기 위치가 아니라 `America/Sao_Paulo`로 고정한다. timestamp는 UTC로 저장한다.
* 엄마에게 원격본·오프라인본 충돌 선택을 요구하지 않는다. 서로 다른 기기는 마지막으로 서버에 도착한 전체 작업본이 우선하며, 같은 기기의 저장 요청은 직렬화한다.
* 하루 보관본은 계획·상파울루 날짜별 한 행이며, 같은 날 저장할 때마다 최신 상태로 갱신한다. 사용자 복원 선택 화면은 Phase 6A에 만들지 않는다.
* 숨김은 목록 표시만 바꾸며 삭제·잠금·`CLOSED`가 아니다. 앱에는 영구 삭제 기능을 만들지 않았다.
* 특별 스냅샷, 셀별 영구 이력, 기존 `localStorage` 이전, 외부 백업, Phase 5 실제 기록·부분 재계산은 이번 범위에서 제외했다.
* Supabase Free 플랜을 기준으로 하며 플랫폼 자동 백업이나 PITR을 안전 계약으로 가정하지 않는다.

## Database Verification

* 11개 pgTAP 검사로 두 기존 Auth 사용자 모두 `ngplan` 작업공간을 읽고 계획을 작성·수정·숨김·복원할 수 있음을 rollback transaction에서 확인했다.
* 익명 역할은 계획을 읽을 수 없고, 인증 역할도 `DELETE` 권한이 없음을 확인했다.
* 문서를 저장할 때 revision이 증가하고 같은 상파울루 날짜의 하루 보관본 한 행이 최신 revision으로 갱신됨을 확인했다.
* 다음 업무 날짜에는 별도 보관본 키를 사용하고 이전 날짜 행을 수정하지 않는 schema·trigger 계약을 확인했다.
* DDL 적용 후 security/performance advisor를 다시 실행했다. ngplan 고유 security 경고는 없었고, 복합 외래 키 인덱스를 보강했다. 공유 프로젝트의 기존 다른 앱 경고와 기존 중복 정책·인덱스는 이번 범위에서 변경하지 않았다.
