# 2026-08-02 ngplan 개발 로그

## Work Summary

계획표의 4단 헤더가 페이지를 세로로 내릴 때 사라지는 문제를 다시 확인했습니다. 첫 수정에서 표 안에 세로 스크롤을 추가하자 시트 높이가 줄어 합계 행이 바로 보이지 않는 문제가 생겨, 시트 높이는 유지하면서 헤더만 고정하는 구조로 다시 수정했습니다.

## Work Completed

- 시트의 세로 높이 제한을 제거해 날짜 행과 합계 행이 원래 시트 높이에 모두 포함되도록 복구했습니다.
- 실제 표의 4단 헤더와 같은 고정용 헤더를 시트 위에 겹쳐 배치했습니다. 고정용 헤더는 화면 읽기 도구에서 중복으로 읽히지 않도록 숨겼습니다.
- 페이지를 내리면 고정용 `ID → 목표값 → 잔액 → 날짜` 헤더만 화면 상단에 남고, 원본 표와 합계 행은 원래 문서 흐름을 유지합니다.
- 표를 가로로 움직일 때 원본 표와 고정용 헤더의 가로 위치가 함께 이동하도록 동기화했습니다.
- 임시 브라우저 fixture로 시트 `clientHeight`와 `scrollHeight`가 동일해 합계 행이 잘리지 않는지, 페이지 스크롤 후 헤더가 상단에 고정되는지, 가로 스크롤 위치가 일치하는지 검증한 뒤 fixture는 삭제했습니다.
- 계획표 컴포넌트 테스트 24개, 타입 검사, 프로덕션 빌드를 통과했습니다.
- 전체 커버리지 테스트 첫 실행에서 시각 전용 헤더까지 회원 순서 검사에 포함되는 기존 테스트 1개가 실패했습니다. 실제 표 안의 회원 헤더만 검사하도록 범위를 좁힌 뒤 전체 714개 테스트와 커버리지 기준을 통과했습니다.

## Decisions

기존 표는 가로 스크롤 상자 안에 있어 원본 헤더에 `position: sticky`만 적용하면 페이지 스크롤에 고정되지 않습니다. 표에 세로 스크롤을 추가하면 고정은 되지만 시트가 짧아져 합계 행이 가려졌습니다. 따라서 원본 표의 전체 높이는 그대로 두고, 시각 전용 헤더를 별도로 겹쳐 페이지에 고정하는 방식을 선택했습니다.

## Current Status

로컬 fixture에서 15개 날짜 행과 합계 행이 세로 잘림 없이 전체 시트 높이에 포함되는 것을 확인했습니다. 페이지를 400px 내린 상태에서도 고정 헤더의 상단 위치가 0으로 유지됐고, 가로 스크롤 320px도 원본 표와 고정 헤더에 동일하게 적용됐습니다. 계획표 실제 화면은 로그인 뒤에 있어 회원 데이터가 필요한 화면까지는 접근하지 못했지만, 전체 714개 테스트·커버리지 기준·타입 검사·프로덕션 빌드는 모두 통과했습니다.

## Next Steps

로그인 후 실제 계획표에서 합계 행까지 원래 높이로 보이는지, 페이지를 내린 뒤 고정 헤더와 첫 날짜 열이 기대한 위치에 남는지 한 번 더 확인합니다.

## Work Completed - 계획표 이미지 만들기

- 계획표 헤더의 동작 순서를 `이미지 만들기 → 설정으로 돌아가기 → 전체 목록으로`로 배치했습니다.
- 일반 창 너비에서도 세 버튼이 화면 오른쪽 밖으로 밀리지 않도록 계획표 헤더 너비를 보정했습니다.
- 큰 체크 항목으로 회원을 1명부터 5명까지 고르는 선택창을 추가했습니다.
- 회원을 누른 순서와 관계없이 실제 계획표에 보이는 순서로 정렬해 이미지에 넣도록 했습니다.
- 맨 왼쪽 날짜 열과 선택한 회원별 `PVP·좌·우` 세 열, 저장된 계획 제목을 함께 출력하도록 했습니다.
- 현재 셀 값뿐 아니라 수당 발생 표시와 실제 차이 빨간 표시도 이미지에 남도록 처리했습니다.
- 생성한 이미지를 먼저 확인한 뒤 저장할 수 있게 했고, 파일 공유를 지원하는 기기에서는 `이미지 공유하기`도 표시하도록 했습니다.
- SVG를 Blob 주소로 읽을 때 캔버스 저장이 차단되는 실제 브라우저 오류를 데이터 주소 방식으로 해결했습니다.
- 이미지에 필요한 스타일만 복사하도록 최적화해 최대 5명 이미지 생성 시간을 실제 확인 화면 기준 약 1.8초로 줄였습니다.
- 이미지 선택 순서, 최대 5명 제한, PNG 생성과 실패 처리, 저장·공유, 헤더 버튼 순서 테스트를 추가했습니다.
- 기존 안내 문구 변경과 맞지 않던 앱 테스트 문구를 현재 화면 문구에 맞췄습니다.

## Decisions - 계획표 이미지 만들기

회원 이름마다 개별 버튼을 붙이지 않고 헤더에 이미지 작업의 시작점을 하나만 두기로 했습니다. 한 사람과 여러 사람을 같은 흐름에서 처리할 수 있고, 이름 열에 반복되는 버튼을 만들지 않아 계획표가 복잡해지지 않기 때문입니다. 출력 순서는 선택 순서가 아니라 시트 순서를 기준으로 고정해 전달 이미지가 원본 계획표와 항상 같은 방향으로 읽히게 했습니다. 최대 인원은 실제 사용 범위인 5명으로 제한했고, 5명 결과가 1828×1684px로 충분히 읽을 수 있는 것을 확인했습니다.
