# 2026-08-01 ngplan Development Log

## Work Summary

두 작업이 같은 작업 폴더에서 동시에 진행된 뒤 전체 변경을 통합 검토했다. 회원별 좌·우 목표 규칙과 이전 내용 화면 개선은 함께 정상적으로 유지되고 있었으며, 안전 저장을 가리키는 일부 화면 문구만 새 용어와 달라 이를 통일했다.

## Work Completed

- 대상 Codex 작업과 현재 Git 변경을 대조해 같은 파일에 합쳐진 프로젝트 제목, 이전 내용 화면, 회원별 좌·우 목표, 저장 형식 이전이 모두 유지되는지 확인했다.
- 회원 삭제 및 자동 계산 적용 확인창에 남아 있던 `보관본`, `사본으로 열기`를 `현재 내용 저장`, `이전 내용 보기`, `새 계획 만들기`로 바꿨다.
- 전체 회귀 검사에서 이전 문구를 기대하던 UI 테스트 1개가 실패해 새 표현을 검증하도록 함께 갱신했다.
- 충돌 표식, 구형 엔진·클라우드 문서 타입, 변경 파일 내 비밀정보와 불필요한 생성 파일이 없는지 확인했다.
- 전체 테스트와 커버리지, TypeScript 검사, 프로덕션 빌드, 배포 파일 스모크 검사를 실행했다.

## Decisions

- 사용자에게 같은 기능을 여러 용어로 설명하지 않도록 안전 저장과 복구 기능은 모든 화면에서 `이전 내용`이라는 표현을 사용한다.
- 새 기간을 만드는 경우에는 회원별 좌·우 목표를 2,500으로 초기화하고, 같은 기간의 이전 내용으로 새 계획을 만드는 경우에는 당시 목표값을 보존한다.
- GitHub Pages 배포가 `main` 푸시에 연결되어 있으므로 최종 통합 변경은 검증 후 `main`에 직접 반영한다.

## Current Status

- `AGENTS.md`는 프로젝트의 사용자·UI 원칙을 담은 파일로 최종 커밋에 포함한다.
- 로컬 전용 환경 변수, 의존성 폴더, 커버리지 결과와 빌드 결과는 Git에서 제외한다.

## Work Summary - 브라우저 뒤로 가기 목록 이동

엄마용 앱 목록에서 ngplan을 연 뒤 회원 등록 또는 플랜 화면에서 브라우저의 뒤로 가기를 누르면, ngplan의 계획 목록을 건너뛰고 `www.nangok.app`으로 돌아가는 문제를 수정했다.

## Work Completed - 브라우저 뒤로 가기 목록 이동

- 계획 목록에서 회원 등록·플랜 편집 화면을 열 때 브라우저 방문 기록을 한 단계 추가하도록 변경했다.
- 편집 화면에서 브라우저 뒤로 가기를 누르면 ngplan 안의 전체 목록을 표시하고 최신 목록을 다시 불러오도록 연결했다.
- 화면의 `전체 목록으로` 버튼도 같은 방문 기록을 사용해, 버튼과 브라우저 뒤로 가기의 결과가 일치하도록 만들었다.
- 회원 등록 화면에서 브라우저 뒤로 가기를 실행해 전체 목록이 표시되고 `www.nangok.app`으로 이동하지 않는 회귀 테스트를 추가했다.

## Decisions - 브라우저 뒤로 가기 목록 이동

- 브라우저 주소는 새 경로를 만들지 않고 현재 ngplan 주소를 유지한다. 화면 상태만 방문 기록에 남겨 기존 배포 주소와 로그인 흐름을 바꾸지 않는다.
- `전체 목록으로` 버튼은 현재 계획을 먼저 저장한 뒤 브라우저 기록으로 돌아간다. 브라우저 뒤로 가기는 편집 화면이 정리될 때 기존 자동 저장 절차가 계속 작동한다.

## Work Summary - 새 저장 형식 동기화 복구

복구본으로 만든 계획과 최신 계획 수정 내용이 이 기기에는 남지만 Supabase에는 저장되지 않는 문제를 조사했다. 앱은 새 문서 형식인 버전 2를 보내고 있었으나 데이터베이스의 프로젝트·자동 보관·하루 보관 제약조건은 버전 1만 허용해 모든 저장 요청을 거절하고 있었다.

## Work Completed - 새 저장 형식 동기화 복구

- 기존 버전 1 자료를 그대로 유지하면서 프로젝트와 두 종류의 보관본이 문서 버전 1과 2를 모두 받을 수 있는 Supabase 마이그레이션을 추가했다.
- 문서 안의 버전과 별도 버전 번호가 서로 일치하는지도 계속 검사하도록 제약조건을 유지했다.
- 수정 전 문서를 자동 보관할 때 수정 후 버전 번호를 붙이던 복구 보관 함수를 바로잡아, 문서 내용과 버전 번호가 항상 함께 이전 상태를 가리키도록 했다.
- 목록의 `이 기기에 저장됨 · 동기화 대기`를 쉬운 두 문장으로 바꾸고 `다시 저장하기` 버튼을 추가했다.
- 정상적인 짧은 저장 대기는 별도로 노출하지 않고, 실제로 인터넷 저장이 끝나지 않은 계획에만 안내가 보이도록 기존 조건을 유지했다.
- 같은 화면에 남아 있던 `클라우드`, `동기화` 표현을 `인터넷에 저장`이라는 한 가지 표현으로 정리했다.

## Decisions - 새 저장 형식 동기화 복구

- 버전 1 자료를 한꺼번에 변환하지 않는다. 기존 자료는 버전 1로 계속 읽고, 새로 저장되는 자료는 버전 2로 받아 데이터 손상 위험을 줄인다.
- 저장 실패 안내를 없애지는 않는다. 사용자가 내용이 인터넷에 저장되지 않았다는 사실과 이 기기에는 남아 있다는 사실을 알아야 하므로, 기술 용어 대신 결과와 안전 상태를 직접 설명한다.

## Current Status - 새 저장 형식 동기화 복구

- 코드, 화면 문구, 회귀 테스트와 데이터베이스 마이그레이션을 작성했다.
- 운영 Supabase에 두 마이그레이션을 적용했다. 기존 계획 10개는 버전 1 상태로 그대로 남아 있고 문서와 버전 번호가 어긋난 자료는 0개다.
- 기존 계획을 트랜잭션 안에서 버전 2로 저장해 프로젝트·하루 보관·복구 보관이 모두 성공하는지 확인한 뒤 전체 시험 변경을 되돌렸다.
- 관련 화면 테스트 21개, 전체 테스트 687개, TypeScript 검사, 프로덕션 빌드와 배포 파일 스모크 검사가 통과했다.
- 로컬 앱은 브라우저에서 로그인 화면까지 정상 렌더링되고 관련 콘솔 오류가 없었다. 저장 실패 카드는 로그인된 목록에서만 볼 수 있어 실제 카드의 시각 검증은 진행하지 못했고, 문구·버튼·재시도 호출은 DOM 회귀 테스트로 확인했다.
- Supabase 보안·성능 검사에서 이번 마이그레이션으로 새로 생긴 경고는 없었다. 표시된 항목은 적용 전부터 있던 다른 앱과 기존 공용 구조의 경고다.

## Next Steps - 새 저장 형식 동기화 복구

- 같은 기기와 브라우저에서 ngplan을 다시 열어, 저장 대기 계획이 자동으로 인터넷에 저장되고 안내가 사라지는지 확인한다.
- 화면 문구 변경과 마이그레이션 파일을 Git에 반영하려면 기존 브라우저 뒤로 가기 변경과 함께 커밋·푸시·배포한다.
