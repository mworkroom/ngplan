# 2026-07-17 ngplan Development Log

## Work Summary

과거 실사용 SRM 작업표의 회원 열 배치를 다시 검토한 결과, 오른쪽 조직을 거울처럼 뒤집는 기존 규칙이 실제 작업 방식과 달랐다. 조직 전체에 동일한 중위 순회(`왼쪽 하위 조직 → 현재 회원 → 오른쪽 하위 조직`)를 적용하도록 수동 계획표 계약과 구현을 수정했다.

## Work Completed

* 수동 계획 스키마의 회원 순서를 루트의 좌우 구분 없이 전체 조직 표준 중위 순회로 변경했다.
* 오른쪽 회원의 왼쪽 하위 회원이 부모보다 먼저, 오른쪽 하위 회원이 부모보다 나중에 표시되는 회귀 테스트를 추가했다.
* 기존 거울 순서로 저장된 수동 계획을 앱 시작 시 날짜와 회원 키로 재조립해 입력값을 보존하고 새 열 순서에 맞추도록 했다.
* 복원된 과거 계획에서 회원별 값이 유지되고 해당 셀을 계속 편집할 수 있는 통합 테스트를 추가했다.
* Phase 3 실행 계획과 정본 요구사항 v2의 거울·역중위 표현을 전체 조직 중위 순회 계약으로 수정했다.
* 31명 완전 이진트리 규모 테스트의 루트 다음 회원 기대값을 새 순서에 맞게 수정했다.
* 관련 테스트 29개와 전체 555개 테스트, TypeScript 타입 검사, 프로덕션 빌드, 배포 산출물 smoke 검사를 실행했다.

## Decisions

* 회원 열은 경로 문자열을 정렬하지 않고 현재 조직의 `parentMemberKey`와 `sideAtParent` 관계를 따라 재귀 중위 순회한다. 경로 접두 회원은 왼쪽과 오른쪽 하위 조직 사이에 와야 하므로 단순 문자열 정렬로는 같은 결과를 보장할 수 없기 때문이다.
* 맨 위 회원은 왼쪽 조직과 오른쪽 조직의 논리적 경계에 두되, 양쪽 회원 수가 다를 때 기하학적 중앙을 만들기 위한 반전이나 빈 열 보정은 하지 않는다.
* 화면 표시 순서만 변경하고 Phase 4의 root-first·LEFT-before-RIGHT 비즈니스 정본 순서는 유지했다. 자동 계획 지문·목적함수·타이브레이커와 UI 배치 계약은 계속 분리한다.
* 저장 형식 버전은 올리지 않았다. 기존 셀은 안정적인 날짜·회원 키를 갖고 있고, 기존 재조립 함수로 값 손실 없이 현재 스키마 순서로 바꿀 수 있기 때문이다.
* 2026-07-13 개발 로그의 거울 규칙 기록은 당시 결정의 이력으로 보존하고, 이번 변경 사유를 오늘 로그에 새로 남겼다.
