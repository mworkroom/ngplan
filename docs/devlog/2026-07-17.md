# 2026-07-17 ngplan Development Log

## Work Summary

과거 실사용 SRM 작업표의 회원 열 배치를 다시 검토해 오른쪽 조직을 통째로 뒤집는 기존 규칙을 먼저 전체 중위 순회로 교체했다. 이후 민경욱 202407A 자료에서 표지판 아래 무표지 회원인 `Han/Yona`, `Simone/Raniton`의 순서가 여전히 반대임을 확인했다. 원본 수식을 다시 추적해, 왼쪽 조직은 표준 중위 순회를 유지하고 오른쪽 조직은 번호 표지판 회원을 기준점으로 두면서 그 기준점의 무표지 오른쪽 하위 묶음만 바깥 방향으로 펼치도록 보완했다.

## Decisions

* 전체 표준 중위 순회만으로는 오른쪽 표지판 아래의 무표지 4레벨 이하 묶음을 원본 SRM 순서로 펼칠 수 없었다. 왼쪽 조직은 표준 중위 순회를 유지하고, 오른쪽 조직의 번호 표지판을 기준점으로 삼아 무표지 왼쪽 묶음은 중위, 무표지 오른쪽 묶음은 역중위로 순회한다.
* 번호 표지판 회원을 만날 때마다 기준점 규칙을 다시 시작한다. 이로써 `2·3·4번` 자체를 거울 반전했던 이전 오류를 반복하지 않으면서 그 아래 무표지 회원만 바깥 방향으로 펼칠 수 있다.
* 오른쪽 최상단 회원에 표지판이 없으면 표준 중위 순회를 사용한다. 표지판이 없는 일반 조직의 기존 표시 동작과 규모 테스트를 보존하기 위한 안전한 기본값이다.
* 맨 위 회원은 왼쪽 조직과 오른쪽 조직의 논리적 경계에 두되, 양쪽 회원 수가 다를 때 기하학적 중앙을 만들기 위한 반전이나 빈 열 보정은 하지 않는다.
* 화면 표시 순서만 변경하고 Phase 4의 root-first·LEFT-before-RIGHT 비즈니스 정본 순서는 유지했다. 자동 계획 지문·목적함수·타이브레이커와 UI 배치 계약은 계속 분리한다.
* 저장 형식 버전은 올리지 않았다. 기존 셀은 안정적인 날짜·회원 키를 갖고 있고, 기존 재조립 함수로 값 손실 없이 현재 스키마 순서로 바꿀 수 있기 때문이다.
* 2026-07-13 개발 로그의 거울 규칙 기록은 당시 결정의 이력으로 보존하고, 이번 변경 사유를 오늘 로그에 새로 남겼다.

## Additional Work — 수동 계획표 최종 행·열 구조 정리

### Work Summary

실사용자의 Excel 작업표와 같은 읽기 순서를 완성하기 위해 수동 계획표에 목표값 행을 복원하고 기존 현황 행을 잔액으로 명확히 바꿨다. 회원 수가 적을 때 열이 화면 전체로 늘어나는 문제와 시트 내부의 불필요한 세로 스크롤도 함께 제거하고, 사용하지 않는 큰 글씨 보기를 없애 작은 글씨 화면 하나로 통일했다.

### Work Completed

* 회원 헤더 아래에 PVP·좌·우 목표값을 각각 표시하는 목표값 행을 추가했다.
* 기존 `현황` 표기를 `잔액`으로 변경하고 `목표값 - 현재 합계` 계산은 그대로 유지했다.
* 헤더를 회원·목표값·잔액·날짜의 4단 구조로 바꾸고 sticky 상단 위치를 `0 / 58 / 88 / 118px`로 조정했다.
* 시트 프레임의 `max-height` 제한을 제거해 표 전체 높이에 맞게 늘어나도록 하고 내부 세로 스크롤을 없앴다.
* `colgroup`과 표의 명시적 전체 너비를 사용해 날짜 50px, PVP 60px, 좌·우 54px의 고정 열 계약을 적용했다.
* 큰 글씨 선택기, 관련 상태와 브라우저 저장 로직, 큰 글씨 전용 CSS를 제거하고 기존 작은 글씨 화면을 단일 화면으로 유지했다.
* 5명·17명 고정 폭 회귀 테스트를 추가했다. 실제 브라우저에서도 5명 표는 940px, 17명 표는 2,956px이며 두 표 모두 내부 세로 높이와 내용 높이가 일치하는지 확인했다.
* 전체 558개 테스트, TypeScript 타입 검사와 프로덕션 빌드를 통과했다.

### Decisions

* 회원 수가 적을 때도 표가 프레임을 채우지 않도록 `min-width: 100%`를 제거했다. 남는 영역은 빈 공간으로 두고 각 회원의 PVP·좌·우 열 너비를 항상 동일하게 유지한다.
* 열 너비를 내용 기반 표 계산에 맡기지 않고 `<colgroup>`과 회원 수 기반 표 전체 너비로 고정했다. 5명과 17명처럼 규모가 달라도 같은 입력 밀도를 보장하기 위한 결정이다.
* 목표값은 새 규칙을 만들지 않고 기존 피라미드 목표 파생 결과를 그대로 표시한다. 잔액 계산과 화면의 목표값이 서로 다른 기준을 갖지 않도록 했다.
* 화면 크기 선택은 실제 사용 환경에서 가치가 없고 과거 `COMFORTABLE` 저장값이 큰 화면을 다시 열 수 있어 기능 자체를 제거했다.
