## Decisions

* 전체 표준 중위 순회만으로는 오른쪽 표지판 아래의 무표지 4레벨 이하 묶음을 원본 SRM 순서로 펼칠 수 없었다. 왼쪽 조직은 표준 중위 순회를 유지하고, 오른쪽 조직의 번호 표지판을 기준점으로 삼아 무표지 왼쪽 묶음은 중위, 무표지 오른쪽 묶음은 역중위로 순회한다.
* 번호 표지판 회원을 만날 때마다 기준점 규칙을 다시 시작한다. 이로써 `2·3·4번` 자체를 거울 반전했던 이전 오류를 반복하지 않으면서 그 아래 무표지 회원만 바깥 방향으로 펼칠 수 있다.
* 오른쪽 최상단 회원에 표지판이 없으면 표준 중위 순회를 사용한다. 표지판이 없는 일반 조직의 기존 표시 동작과 규모 테스트를 보존하기 위한 안전한 기본값이다.
* 맨 위 회원은 왼쪽 조직과 오른쪽 조직의 논리적 경계에 두되, 양쪽 회원 수가 다를 때 기하학적 중앙을 만들기 위한 반전이나 빈 열 보정은 하지 않는다.
* 화면 표시 순서만 변경하고 Phase 4의 root-first·LEFT-before-RIGHT 비즈니스 정본 순서는 유지했다. 자동 계획 지문·목적함수·타이브레이커와 UI 배치 계약은 계속 분리한다.
* 저장 형식 버전은 올리지 않았다. 기존 셀은 안정적인 날짜·회원 키를 갖고 있고, 기존 재조립 함수로 값 손실 없이 현재 스키마 순서로 바꿀 수 있기 때문이다.
* 2026-07-13 개발 로그의 거울 규칙 기록은 당시 결정의 이력으로 보존하고, 이번 변경 사유를 오늘 로그에 새로 남겼다.

## Additional Work — 수동 계획표 최종 행·열 구조 정리

### Work Summary

실사용자의 Excel 작업표와 같은 읽기 순서를 완성하기 위해 수동 계획표에 목표값 행을 복원하고 기존 현황 행을 잔액으로 명확히 바꿨다. 회원 수가 적을 때 열이 화면 전체로 늘어나는 문제와 시트 내부의 불필요한 세로 스크롤도 함께 제거하고, 사용하지 않는 큰 글씨 보기를 없애 작은 글씨 화면 하나로 통일했다.

### Work Completed

* 회원 헤더 아래에 PVP·좌·우 목표값을 각각 표시하는 목표값 행을 추가했다.
* 기존 `현황` 표기를 `잔액`으로 변경하고 `목표값 - 현재 합계` 계산은 그대로 유지했다.
* 헤더를 회원·목표값·잔액·날짜의 4단 구조로 바꾸고 sticky 상단 위치를 `0 / 58 / 88 / 118px`로 조정했다.
* 시트 프레임의 `max-height` 제한을 제거해 표 전체 높이에 맞게 늘어나도록 하고 내부 세로 스크롤을 없앴다.
* `colgroup`과 표의 명시적 전체 너비를 사용해 날짜 50px, PVP 60px, 좌·우 54px의 고정 열 계약을 적용했다.
* 큰 글씨 선택기, 관련 상태와 브라우저 저장 로직, 큰 글씨 전용 CSS를 제거하고 기존 작은 글씨 화면을 단일 화면으로 유지했다.
* 5명·17명 고정 폭 회귀 테스트를 추가했다. 실제 브라우저에서도 5명 표는 940px, 17명 표는 2,956px이며 두 표 모두 내부 세로 높이와 내용 높이가 일치하는지 확인했다.
* 전체 558개 테스트, TypeScript 타입 검사와 프로덕션 빌드를 통과했다.

### Decisions

* 회원 수가 적을 때도 표가 프레임을 채우지 않도록 `min-width: 100%`를 제거했다. 남는 영역은 빈 공간으로 두고 각 회원의 PVP·좌·우 열 너비를 항상 동일하게 유지한다.
* 열 너비를 내용 기반 표 계산에 맡기지 않고 `<colgroup>`과 회원 수 기반 표 전체 너비로 고정했다. 5명과 17명처럼 규모가 달라도 같은 입력 밀도를 보장하기 위한 결정이다.
* 목표값은 새 규칙을 만들지 않고 기존 피라미드 목표 파생 결과를 그대로 표시한다. 잔액 계산과 화면의 목표값이 서로 다른 기준을 갖지 않도록 했다.
* 화면 크기 선택은 실제 사용 환경에서 가치가 없고 과거 `COMFORTABLE` 저장값이 큰 화면을 다시 열 수 있어 기능 자체를 제거했다.

## Additional Work — 누적 PVP와 기간 목표 산식 분리

### Work Summary

실사용 Excel의 맨 위 목표값 `PVP 0 / 좌 22,810 / 우 22,540`과 앱의 `2,400 / 25,500 / 27,300`이 다른 원인을 추적했다. 앱이 선택 PVP 목표 전체와 누적 PVP 시작값을 보름 좌·우에 다시 사용하고 있었던 것이 원인이었다. 누적 PVP는 개인 달성 현황과 자격 누계에만 쓰고, 목표 행과 보름 좌·우에는 이번 기간 신규 PVP만 한 번 반영하도록 계산 계약을 분리했다.

### Work Completed

* 목표 행의 회원별 PVP를 `MAX(0, 선택 목표 - 누적 PVP 시작값)`으로 계산하고 이 신규 PVP 부족분을 기존 피라미드 산식으로 하위부터 합산하도록 수정했다.
* 맨 위 회원의 좌·우 목표는 재귀 합산값과 22,500 중 큰 값을 사용하도록 하한을 추가했다.
* 잔액 행의 PVP는 신규 PVP 목표에서 이번 기간 신규 PVP 합계만 빼도록 바꿔 누적 PVP가 두 번 차감되지 않게 했다.
* 보름 마감의 작은 쪽 적용량을 `누적 PVP 시작값 + 신규 PVP`에서 `이번 기간 신규 PVP`로 변경했다. 누적 PVP는 개인 목표 부족분과 qualification 누계에는 계속 사용한다.
* 자동 후보 생성기가 모든 회원의 새 2,500 산식을 채우고 맨 위 원본 좌·우를 각각 22,500 이상 만들도록 보완했다. 독립 후보 검증기도 같은 맨 위 하한을 확인한다.
* 규칙·엔진 버전을 `5.0.0`으로 올려 이전 계산 후보와 체크포인트가 새 계약으로 오인되지 않도록 했다.
* 요구사항, 기술 설계, 계산 사례, 로드맵과 Phase 4 실행 계획을 새 PVP 원천·맨 위 하한 계약에 맞춰 동기화했다.
* 누적 PVP 차감, PVP 잔액 중복 차감 방지, 맨 위 22,500 하한, 자동 후보 생성·검증 회귀 테스트를 추가·갱신했다.

### Decisions

* 누적 PVP 2,400은 첫날에 사용할 실적이 아니라 평생 달성 현황이다. 따라서 선택 목표의 남은 신규 PVP를 0으로 만들 수는 있지만 보름 좌·우 작은 쪽이나 상위 조직 신규 실적에는 다시 더하지 않는다.
* 모든 회원의 기본 좌·우 판정 목표 2,500은 유지한다. 맨 위 회원만 팀 전체 운영 목표로 원본 좌·우 각각 22,500 하한을 추가하며, 구조상 재귀 목표가 더 크면 그 값을 사용한다.
* 아직 실사용자에게 재확인이 필요한 목표 1,500·2,400 회원의 13회 커미션 정책은 이번 변경에 포함하지 않았다. 이번 작업은 확인이 끝난 산술 계약만 수정했다.

* 우선 회원의 왼쪽·오른쪽 조직을 각각 이동하는 후보와 여러 우선 회원을 함께 조정하는 제한된 복합 후보를 추가했다. PVP 자격 날짜와 마지막 영업일은 고정하고 직접 좌·우 일정만 이동해 총량과 마지막 날 조건을 보존했다.
* 말단 회원의 목표 행과 자동 후보 방향을 `PVP 700 / 좌 2,500 / 우 1,800` 관례로 통일했다.
* 결과 화면에서 후속 700 집단 통계를 `그 외 700 목표`라고 표시해 깊이 2·3 우선 회원이 제외된 범위를 명확히 했다.
* 규칙·엔진 버전을 `6.0.0`, 자동 계획 정책·목적 버전을 `4.0.0`으로 올려 과거 후보와 체크포인트가 새 계약으로 복원되지 않게 했다.
* 요구사항, 기술 설계, 계산 사례, Phase 4 실행 계획과 로드맵의 관련 계약만 새 산식·57명·구조 기반 우선순위에 맞춰 갱신했다.
* 전체 564개 테스트와 TypeScript 타입 검사를 통과했다.

### Decisions

* 7,500·22,500·67,500을 회원 수로 고르는 표는 만들지 않는다. 소형 약 7,500, 17명 사례 22,810·22,540, 대형 사례 67,700·67,500 같은 값은 조직 구조와 시작 PVP에서 자연스럽게 나온 재귀 결과를 그대로 사용한다.
* 이름 앞의 2·3번 표지판은 사람이 잘못 붙일 수 있으므로 계산 기준으로 사용하지 않는다. 루트를 깊이 1로 두고 실제 부모 연결에서 깊이 2·3을 계산한다.
* 여러 집단에서 같은 회원을 중복 보상하지 않는다. 깊이 2·3 집단을 먼저 비교하고, 그 회원과 루트를 뺀 나머지 목표 집단만 후속 비교한다.
* 정확 솔버가 없는 현재 구조에서는 목적함수만 추가해도 새 배치를 만들 수 없다. 따라서 좌·우 단일 이동과 제한된 복합 이동을 함께 생성하되 57명에서도 약 156개 수준으로 상한을 두어 조합 폭발을 막는다.
* 57명 전원의 누적 PVP 시작값이 0인 극단 사례는 6,000 이상 미확정 수당 단계가 발생해 정본 검증 후보를 보장하지 않는다. 수당 금액을 추측하지 않는 기존 fail-closed 원칙을 유지하며, 현실적인 혼합 시작값 조직에서는 검증 후보가 생성되는 것을 확인했다.
* 오늘 앞선 기록의 22,500 하한과 13회 정책 보류 내용은 당시 결정 이력으로 남기고, 이번 추가 기록에서 새로 확인된 계약과 변경 이유를 명시한다.

### Current Status
