# 2026-07-19 ngplan Development Log

## Work Summary

운영자가 말하는 “수당 8회·20회”가 수당 발생 날짜 수가 아니라 300단계 수당 금액을 기준으로 환산한 횟수라는 점이 확정되었다. 기존 Phase 4는 일반 회원 공평성을 정상 커미션 발생일 수로 비교하고 있어 실제 운영 의도와 달랐다. 수당 발생일과 환산 횟수를 분리하고, 자동 계획의 일반 공평성 목적을 환산 횟수 기준으로 교체했다. 관련 작업은 기존 Phase 4 GitHub Issue #5의 후속 계약 개정으로 정리했다.

## Work Completed

* 확정 수당 단계를 `300=1회`, `700=2회`, `1,500=4회`, `2,400=8회`로 환산하는 도메인 함수를 추가했다.
* 보름 평가에 `commissionDays`와 별도로 `commissionEquivalentUnits`를 추가했다. 6,000·20,000·60,000처럼 환산표가 없는 단계가 포함되면 합계를 추측하지 않고 미확정으로 남긴다.
* 목표 700의 권장 기준을 발생일 8일에서 300단계 기준 환산 8회로 바꿨다. 필수 보름 목표가 아니라 기존과 같은 소프트 권장값이다.
* 자동 계획의 조직 깊이 2·3, 나머지 목표 1,500·2,400, 나머지 목표 700 공평성 벡터를 모두 발생일 수에서 환산 횟수로 교체했다. 맨 위 회원의 동적 `U` 목표는 영업일별 수당 발생을 유지해야 하므로 발생일 기준을 그대로 보존했다.
* 자동 계획 미리보기와 수동 회원 결과에 수당 발생일과 환산 횟수를 구분해 표시했다. 날짜별 발생 내역에도 단계별 환산 횟수를 함께 표시한다.

## Decisions

* “수당 발생일”은 한 회원에게 하루 최대 한 번인 날짜 수이고, “수당 환산 횟수”는 300단계 금액을 1회로 본 운영 단위로 정의했다. 같은 회원이 700단계를 4일 받으면 발생일은 4일, 환산 횟수는 8회다.
* 일반 회원 공평성은 환산 횟수만 비교한다. 따라서 환산 총량이 같으면 4일에 받은 계획과 8일에 받은 계획은 이 목적 단계에서 동률이다.
* 맨 위 회원의 전 기간 활동 목표는 팀 전체가 앞부분에 멈추지 않게 하는 별도 운영 규칙이므로 `rootCommissionGoalShortfallDays`를 계속 사용한다.
* 6,000 이상 단계의 실제 수당과 환산 횟수는 확정되지 않았다. 수동 결과는 발생일과 미확정 상태를 보여주고, 자동 계획은 기존 수당표 fail-closed 경계에서 순위 계산을 중단한다.
* 브라우저 작업 스냅샷 전체 버전은 유지해 회원 설정과 수동 입력을 잃지 않게 했고, 의미가 달라진 자동 후보 체크포인트만 `3.0.0`으로 올려 이전 일수 벡터 후보를 복원하지 않게 했다.

* 동일한 17명 입력으로 새 후보를 생성해 Mirelle·Sandra·Kelly 등 목표 1,500·2,400 회원의 환산 미달이 이전 결과보다 줄었는지 운영자 검수를 진행한다.

* 상한은 충분하지만 후보 생성기가 달성하지 못하는 사례가 반복되면 총 PV를 늘리지 않는 날짜 프로필 후보를 추가한다.

## Work Summary — 좌우 분기 동기화와 엑셀 기준 자동 회귀

독립적인 직접 PV 날짜 프로필만으로는 Mirelle·Sandra·Kelly처럼 좌우 하위 조직의 실적이 같은 날 맞아야 하는 회원의 수당 단계를 충분히 만들지 못했다. 2024년 7월 실사용 엑셀을 회귀 기준으로 삼아, 좌우 전체 가지를 함께 정렬하는 후보와 기존 가지의 내부 패턴을 보존한 채 날짜만 회전하는 후보를 추가했다. 엑셀 결과는 운영 규칙으로 고정하지 않고 새 알고리즘이 과거 결과보다 나빠지는지를 자동 탐지하는 개발 기준으로 사용했다.

## Work Completed — 좌우 분기 동기화와 엑셀 기준 자동 회귀

* 목표 1,500·2,400 회원의 좌우 가지에서 편집 가능한 직접 실적 풀 전체를 수집하고, 양쪽의 공통 총량을 `300`, `300·200·400`, `700`, `1,500`, `2,400` 프로필로 같은 날짜에 정렬하는 후보 생성기를 추가했다.
* 하위 회원에게 이미 유리한 내부 날짜 패턴은 유지하면서 한쪽 가지 전체의 `PVP·SELF_LEFT·SELF_RIGHT`를 영업일 단위로 회전하는 후보를 추가했다.
* 작은 조직은 현재 최선 후보 외에 회원별 환산 횟수가 좋은 다양한 시드도 보존해 최대 4회 재탐색하고, 큰 조직은 비용을 제한하기 위해 최대 2회 재탐색하도록 worker 후보 선택기를 확장했다.
* 모든 새 후보는 회원별·필드별 직접 PV 총량을 보존하며, 정본 검증기와 기존 목적함수 비교를 통과해 현재 전역 최선보다 엄격히 좋아질 때만 게시되도록 했다.
* 2024년 7월 17명 고정 fixture에 엑셀 기준과 앱 결과를 자동 비교하는 회귀 검사를 추가했다. 엑셀의 Mirelle·Sandra·Kelly 환산 횟수 `18·20·17`에 대해 앱은 `20·20·20`, 차이는 `+2·0·+3`이다.
* 같은 fixture에서 총 직접 PV `45,350`, 확인 수당 합계 `12,060,000원`, 맨 위 회원 `13/13영업일`을 함께 고정해 수당만 좋아지고 총량이나 기간 계약이 깨지는 회귀를 방지했다.
* 자동 계획 미리보기에 목표 1,500·2,400 및 목표 700 회원의 `수당 발생일·환산 횟수·기준 상한·상한까지 남은 횟수`를 한 표로 표시했다.
* Phase 4 실행 계획에 좌우 분기 동기화, 가지 회전, 다중 시드 재탐색과 2024년 7월 회귀 기준을 기록했다.

## Decisions — 좌우 분기 동기화와 엑셀 기준 자동 회귀

* 엑셀 환산 횟수는 프로덕션 최적화 목표나 회원별 하한으로 하드코딩하지 않는다. 과거 수작업보다 알고리즘이 나빠졌는지 확인하는 테스트 증거로만 유지한다.
* 앱 화면에는 엑셀과의 차이가 아니라 현재 계획 자체의 수당 발생일·환산 횟수·상한·미달을 자동 표시한다. 엑셀 값은 앱 입력에 포함되지 않으므로 개발 회귀 검사에서만 자동 비교한다.
* 마커는 계속 위치 표시로만 취급한다. 후보 집중 대상은 루트를 제외한 목표 1,500·2,400 회원과 현재 목적함수의 상한 미달 순서로 결정한다.
* 가지 회전으로 PVP 날짜가 바뀌는 후보도 허용하되 회원별 PVP 총량은 보존하고, 자격·수당·목표를 정본 검증기가 다시 계산해 통과한 후보만 사용한다.
* 이번 탐색도 휴리스틱이며 정확 최적해 증명이 아니다. 더 좋은 검증 후보를 찾았다는 사실을 `OPTIMAL` 또는 `INFEASIBLE` 주장으로 확대하지 않는다.
