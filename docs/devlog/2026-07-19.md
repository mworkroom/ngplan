# 2026-07-19 ngplan Development Log

## Work Summary

운영자가 말하는 “수당 8회·20회”가 수당 발생 날짜 수가 아니라 300단계 수당 금액을 기준으로 환산한 횟수라는 점이 확정되었다. 기존 Phase 4는 일반 회원 공평성을 정상 커미션 발생일 수로 비교하고 있어 실제 운영 의도와 달랐다. 수당 발생일과 환산 횟수를 분리하고, 자동 계획의 일반 공평성 목적을 환산 횟수 기준으로 교체했다. 관련 작업은 기존 Phase 4 GitHub Issue #5의 후속 계약 개정으로 정리했다.

## Work Completed

* 확정 수당 단계를 `300=1회`, `700=2회`, `1,500=4회`, `2,400=8회`로 환산하는 도메인 함수를 추가했다.
* 보름 평가에 `commissionDays`와 별도로 `commissionEquivalentUnits`를 추가했다. 6,000·20,000·60,000처럼 환산표가 없는 단계가 포함되면 합계를 추측하지 않고 미확정으로 남긴다.
* 목표 700의 권장 기준을 발생일 8일에서 300단계 기준 환산 8회로 바꿨다. 필수 보름 목표가 아니라 기존과 같은 소프트 권장값이다.
* 자동 계획의 조직 깊이 2·3, 나머지 목표 1,500·2,400, 나머지 목표 700 공평성 벡터를 모두 발생일 수에서 환산 횟수로 교체했다. 맨 위 회원의 동적 `U` 목표는 영업일별 수당 발생을 유지해야 하므로 발생일 기준을 그대로 보존했다.
* 자동 계획 미리보기와 수동 회원 결과에 수당 발생일과 환산 횟수를 구분해 표시했다. 날짜별 발생 내역에도 단계별 환산 횟수를 함께 표시한다.
* 환산 목적 벡터와 표시 통계 shape 변경에 맞춰 ruleset·engine을 `7.0.0`, policy·objective를 `6.0.0`, request·fingerprint·checkpoint·model·certificate·worker protocol을 `3.0.0`으로 올렸다.
* 요구사항, 기술 설계, 계산 사례, 로드맵과 Phase 4 실행 계획을 같은 계약으로 동기화했다. `COUNT-004`에 발생일 4일과 환산 15회의 차이 및 700단계 4일이 환산 8회라는 정답 사례를 추가했다.
* 엔진·목적함수·체크포인트·worker protocol·수동/자동 UI 테스트를 갱신하고 환산 `1·2·4·8`이 실제 공평성 벡터에 들어가는 직접 테스트를 추가했다.

## Decisions

* “수당 발생일”은 한 회원에게 하루 최대 한 번인 날짜 수이고, “수당 환산 횟수”는 300단계 금액을 1회로 본 운영 단위로 정의했다. 같은 회원이 700단계를 4일 받으면 발생일은 4일, 환산 횟수는 8회다.
* 일반 회원 공평성은 환산 횟수만 비교한다. 따라서 환산 총량이 같으면 4일에 받은 계획과 8일에 받은 계획은 이 목적 단계에서 동률이다.
* 맨 위 회원의 전 기간 활동 목표는 팀 전체가 앞부분에 멈추지 않게 하는 별도 운영 규칙이므로 `rootCommissionGoalShortfallDays`를 계속 사용한다.
* 6,000 이상 단계의 실제 수당과 환산 횟수는 확정되지 않았다. 수동 결과는 발생일과 미확정 상태를 보여주고, 자동 계획은 기존 수당표 fail-closed 경계에서 순위 계산을 중단한다.
* 브라우저 작업 스냅샷 전체 버전은 유지해 회원 설정과 수동 입력을 잃지 않게 했고, 의미가 달라진 자동 후보 체크포인트만 `3.0.0`으로 올려 이전 일수 벡터 후보를 복원하지 않게 했다.
