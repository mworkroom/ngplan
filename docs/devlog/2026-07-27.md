# 2026-07-27 ngplan Development Log

## Work Summary - 플랜 진입 UX 단순화

입력 완료 뒤 별도의 준비 완료 카드에서 버튼을 다시 찾아야 했던 흐름을 없애고, 설정 화면 상단에서 수동 플랜 또는 자동 플랜으로 바로 이동할 수 있도록 정리했다. 같은 의미의 상태 문구가 여러 번 반복되어 화면의 핵심 행동이 흐려지는 문제도 함께 해소했다.

## Work Completed - 플랜 진입 UX 단순화

- 상단 동작을 `수동 플랜 열기`와 `자동 플랜 만들기`로 명확히 구분했다.
- 두 버튼을 누르는 순간 입력값을 검증하고, 유효할 때 선택한 화면으로 바로 이동하도록 했다.
- `계획표 준비 완료`, `플랜을 만들 준비가 되었습니다`, `준비 완료` 문구와 준비 완료 카드를 제거했다.
- 다중 사용자 작업 표시를 위해 남아 있던 `입력 중` 상태를 제거했다.
- 화면 전환 뒤 새 화면 제목으로 초점이 이동하도록 하고 키보드 Enter 동작을 회귀 테스트에 포함했다.
- 모바일 너비에서 상단 버튼이 한 열로 배치되고 화면 밖으로 넘치지 않도록 반응형 스타일을 보완했다.

## Decisions - 플랜 진입 UX 단순화

- 수동 플랜과 자동 플랜은 서로 다른 최종 행동이므로, 중간 `플래너 생성` 단계로 묶지 않고 처음부터 각각의 행동명으로 노출하기로 했다.
- 준비 상태를 반복해서 알리는 것보다 사용자가 다음 행동을 즉시 선택할 수 있게 하는 편이 인지 부담이 적다고 판단했다.
- 화면 전환은 시각적 변화만으로 알리지 않고 새 화면 제목으로 초점을 옮겨 키보드 및 보조기기 사용자도 전환을 인지할 수 있게 했다.

## Work Summary - 보관함 회원 다시 넣기 UX

회원을 조직도에서 잠시 빼 둔 상태를 개발자 관점의 `새 위치 결정 대기`가 아니라 사용자가 이해하기 쉬운 `보관함`으로 표현했다. 다시 넣는 방법과 정보 화면으로 돌아가는 방법도 화면에서 바로 알 수 있도록 흐름을 정리했다.

## Work Completed - 보관함 회원 다시 넣기 UX

- 대기 회원 영역의 제목을 `보관함에 있는 회원`으로 바꾸고, 원하는 빈 자리의 `+` 버튼을 누르라는 다음 행동을 안내했다.
- 보관함의 회원 항목 전체를 큰 `정보 보기` 버튼으로 바꾸어 다른 회원을 선택한 뒤에도 해당 회원의 우측 정보 화면으로 돌아올 수 있게 했다.
- 선택 중인 보관함 회원은 `aria-pressed` 상태와 배경색으로 구분되도록 했다.
- 우측 회원 정보 영역의 안내를 빈 자리의 `+` 버튼과 `이 자리에 넣기` 버튼을 순서대로 설명하는 문구로 교체했다.
- 빈 자리 선택창의 제목을 `누가 들어갈까요?`로 바꾸고, `새 회원 만들기`와 보관함 회원을 넣는 행동을 쉬운 문장으로 설명했다.
- 보관함에 넣은 직후의 알림과 검증 오류 문구도 같은 용어와 행동 순서를 사용하도록 통일했다.
- 보관함 회원 재선택과 키보드 Enter 선택을 자동 테스트에 추가했다.
