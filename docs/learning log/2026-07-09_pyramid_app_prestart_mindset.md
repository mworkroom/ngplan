# 2026-07-09 Pyramid App Pre-start Mindset Learning Log

## 주제

피라미드 앱을 시작하기 전 느끼는 부담감과 회피감의 원인을 정리했다. 표면적으로는 앱 자체가 어려울 것 같다는 두려움이지만, 실제로는 지난 한 달 동안 가격표 앱을 만들며 겪은 개발 환경 삽질, 툴 사용법 학습, 배포 문제, GitHub 작업 흐름 혼선이 누적된 결과에 가깝다.

## 현재 감정

피라미드 앱은 이제 시작해야 한다고 생각하지만, 계속 미루고 싶은 마음이 있다. 머리 아플 것이 예상되고, 가격표 앱보다 더 어려울 것이라는 말이 남아 있어 시작 전 부담감이 커졌다. 그래서 “오늘은 그냥 아주 작은 앱이나 만들자”는 식으로 더 쉬운 작업으로 회피하려는 흐름이 생겼다.

이 감정은 단순히 게으름이나 의지 부족이 아니라, 이전 프로젝트에서 예상하지 못한 문제들이 반복적으로 터졌던 경험에서 나온 방어 반응에 가깝다.

## 배경: 가격표 앱에서 겪은 예상 밖의 비용

처음 가격표 앱은 단순한 가격 검색 앱 정도로 생각했다. 그러나 실제로는 다음 요소들이 계속 추가되며 프로젝트가 커졌다.

- Supabase 연결
- 권한 분리
- 관리자/센터/사업자 화면 구분
- Google 로그인
- GitHub Pages 배포
- 도메인 연결
- 모바일 홈 화면 추가
- PWA, manifest, service worker 문제
- 포르투갈어 상품명 정리
- 모바일 UI 수정
- 인쇄/PDF 화면 고려
- 실제 사용자 안내 문구 작성

앱 자체의 기능뿐 아니라 개발 도구와 배포 환경을 배우는 비용이 동시에 발생했다.

## 핵심 깨달음 1: 앱을 만든 것이 아니라 개발 환경까지 같이 배웠다

지난 한 달은 가격표 앱 하나를 만든 시간이기도 했지만, 실제로는 다음을 동시에 배운 시간이었다.

- VS Code 사용 흐름
- `npm run dev`로 로컬 서버를 켜는 방식
- React/Vite 프로젝트 구조
- GitHub 수동 업로드의 한계
- VS Code에서 Git commit/push 하는 방법
- `node_modules`와 `dist`를 Git에 올리면 안 되는 이유
- GitHub Pages 배포 경로와 로컬 개발 경로가 다를 수 있다는 점
- DNS 연결과 SSL 인증서가 즉시 안정화되지 않을 수 있다는 점
- 모바일 Safari와 iOS 홈 화면 추가의 특수성

그래서 실제 시간 소모의 상당 부분은 “앱 구현”이 아니라 “앱을 만들 수 있는 작업 환경을 이해하는 비용”이었다.

## 핵심 깨달음 2: 초보 삽질은 손해가 아니라 선결제다

당시에는 맨땅에 헤딩하는 느낌이 강했다. 한 달 내내 GitHub에 수동 업로드를 하다가 뒤늦게 VS Code와 GitHub를 제대로 연결해야 한다는 것을 깨달았고, 그 과정에서 하던 작업을 멈추고 툴 사용법을 다시 배워야 했다.

Pay Me Mom도 금방 만들 수 있을 것이라 예상했지만, 웹폰트 하나를 적용하고 화면을 확인하려는 과정에서 로컬 개발 서버와 Vite 설정 문제를 다시 겪었다. 작은 앱이어도 React/Vite 기반이면 확인 환경을 갖추는 데 시간이 들어간다는 점을 체감했다.

이런 삽질은 당장은 시간을 잡아먹었지만, 다음 프로젝트에서는 같은 문제를 훨씬 빠르게 알아볼 수 있게 해준다. 즉, 가격표 앱과 Pay Me Mom에서 쓴 시간 일부는 피라미드 앱을 위한 선결제 비용이었다.

## 핵심 깨달음 3: 피라미드 앱의 두려움은 “기능 난이도”만의 문제가 아니다

피라미드 앱을 두려워하는 이유는 세 가지로 보인다.

1. 가격표 앱보다 구조가 복잡할 것이라는 예상
2. 또 시간이 많이 걸릴 것이라는 피로감
3. 예상 밖의 환경 문제와 설정 문제를 다시 만날 수 있다는 기억

하지만 실제로 피라미드 앱에서 어려울 부분은 가격표 앱과 다르다.

가격표 앱은 배포, 도메인, 로그인, 권한, 모바일, 다국어 같은 외부 요소가 넓게 퍼져 있었다. 반면 피라미드 앱은 사람 간 관계, 상하위 구조, 계산 규칙, 예외 처리, 데이터 검증이 핵심이 될 가능성이 높다.

즉, 피라미드 앱은 환경 삽질보다는 데이터 구조와 로직이 더 중요한 프로젝트다.

## 마음가짐 전환

피라미드 앱을 “완성해야 할 큰 앱”으로 보면 시작 전부터 압도된다. 대신 첫 단계는 다음처럼 아주 작게 잡는 편이 낫다.

- 사람을 등록한다.
- 각 사람에게 상위자 또는 추천인을 연결한다.
- 연결된 관계를 목록이나 트리로 확인한다.
- 잘못 연결한 사람을 수정할 수 있다.

이 단계는 피라미드 앱 전체가 아니라 “관계형 주소록”에 가깝다. 계산, 실적, 등급, 기간별 집계는 그다음에 올릴 수 있다.

## 다음 프로젝트에 적용할 원칙

1. 처음부터 완성 앱을 만들려고 하지 않는다.
2. 첫날 목표는 데이터 구조와 최소 입력 화면으로 제한한다.
3. 배포, 도메인, 디자인, 모바일 최적화는 MVP 이후로 미룬다.
4. 이미 겪은 환경 삽질은 다시 처음부터 겪지 않는다는 점을 기억한다.
5. 피라미드 앱은 “가격표 앱보다 큰 괴물”이 아니라 “가격표 앱에서 배운 환경 위에 얹는 첫 로직 중심 앱”으로 본다.

## 정리

현재의 두려움은 타당한 신호다. 가격표 앱에서 예상보다 많은 시간을 썼고, 그 과정에서 앱 구현 외의 학습 비용이 크게 발생했기 때문이다. 그러나 그 삽질은 다음 프로젝트의 비용을 줄이는 역할도 한다.

피라미드 앱은 처음부터 완성형으로 접근하지 않고, 사람과 관계를 저장하는 작은 MVP부터 시작하면 된다. 핵심은 “오늘 피라미드 앱을 끝낸다”가 아니라 “오늘 사람을 연결할 수 있는 첫 구조를 만든다”로 범위를 줄이는 것이다.
