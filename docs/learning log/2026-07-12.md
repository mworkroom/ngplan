# Learning Log — 2026-07-12

## 사용자용 한국어는 개발 용어의 번역이 아니다

피라미드 앱을 만드는 과정에서 예상하지 못한 문제가 드러났다. 기능 구현보다도 50–70대 사용자가 바로 이해할 수 있는 한국어 문구를 만드는 일이 훨씬 어려웠다.

Codex가 작성한 문구에는 `루트 회원`, `잎 회원`, `자식 객체`, `부모 종속성`, `슬롯`, `서브트리`, `승격`, `정수`처럼 영어 개발 용어를 직역한 표현이 반복되었다. 문법적으로 틀린 문장은 아니지만, 실제 사용자가 일상에서 쓰는 한국어와는 거리가 멀었다.

예를 들어 다음과 같은 문제가 있었다.

- `root member` → `루트 회원`
- `leaf member` → `잎 회원`
- `child object` → `자식 객체`
- `parent dependency` → `부모 종속성`
- `숫자는 정수로만 입력해주세요` → 사용자는 `정수`의 의미부터 다시 물어야 함

이를 통해 코드 내부의 개념과 사용자 화면의 문구를 분리해야 한다는 점을 배웠다. 내부 변수명과 타입은 기술 용어를 유지해도 되지만, 화면에서는 사용자가 지금 무엇을 해야 하는지와 어떤 일이 일어나는지만 설명해야 한다.

## 문구를 고치는 기준

핵심 원칙은 개념의 이름을 알려주지 않고 실제 동작을 설명하는 것이다.

- `루트 회원` → `기준 회원`, `맨 위 회원`, 또는 문장으로 풀어쓰기
- `부모 회원` → `바로 위 회원`
- `자식 회원` → `바로 아래 회원`
- `직계 자식` → `바로 아래에 연결된 회원`
- `서브트리` → `이 회원 아래에 있는 전체 회원` 또는 `아래 조직`
- `정수만 입력` → `소수점 없이 입력`

반복해서 이름을 불러야 하는 핵심 개념만 용어로 정하고, 나머지는 문장으로 풀어쓰는 편이 낫다. 정확한 기술 용어보다 사용자가 즉시 이해하는 표현이 우선이다.

## 조직도 관련 표현

`조직 그림`은 번역투가 강해 `조직도`로 바꾸는 것이 자연스럽다.

기존 문구:

> 이 회원은 지금 조직 그림의 자리에 연결되어 있지 않습니다. 아래 회원들의 새 위치를 다시 정해야 합니다.

수정 방향:

> 이 회원은 현재 조직도에 들어가 있지 않습니다. 아래 회원들을 어디에 둘지 다시 정해야 합니다.

`연결되어 있지 않습니다`, `새 위치`처럼 추상적인 표현보다 `들어가 있지 않습니다`, `어디에 둘지`처럼 일상적인 동사를 사용하는 편이 이해하기 쉽다.

## 반복되는 카드 UI 문구

각 회원 카드에 `하위 조직 펼치기 / 하위 조직 접기`가 반복되자 화면이 지나치게 복잡해 보였다. 표현 자체가 틀린 것은 아니지만, 카드마다 같은 단어가 반복되면 내용보다 버튼이 먼저 보인다.

화면 표시용 문구는 다음처럼 줄일 수 있다.

- `아래 보기`
- `접기`

정확한 설명은 `aria-label="하위 조직 펼치기"`처럼 접근성 속성에 유지하고, 사용자가 보는 버튼은 짧게 표시하는 방식이 적절하다.

## 기간 명칭 문제

한 달을 전반기와 후반기로 나누는 특수 기간을 Codex는 처음에 `반월`이라고 표현했다. 뜻은 맞지만 실제 사용자가 쓰는 말은 아니었다.

현장에서는 이 기간을 `직급 기간`이라고 부른다는 사실을 확인했다. 다만 UI에 `이번 직급 기간 PVP 목표`라고 쓰면 다소 길고 딱딱하다.

후보는 다음과 같다.

- `이번 기간 PVP 목표`
- `이번 직급 목표`
- `현재 기간 PVP 목표`
- 날짜가 명확할 경우 `7월 상반기 PVP 목표`, `7월 하반기 PVP 목표`

앱 전체가 직급 계산용이라는 맥락이 이미 있으므로, 반복되는 화면에서는 `이번 기간 PVP 목표`처럼 줄이는 편이 가장 무난하다.

## 최종 정리

이번 작업을 통해 사용자용 한국어는 영어 개발 용어를 번역하는 작업이 아니라, 사용자가 실제로 행동할 수 있도록 다시 쓰는 작업이라는 점을 확인했다.

앞으로 사용자 화면의 문구는 다음 기준으로 검토한다.

1. 컴퓨터나 조직도 용어를 모르는 사람도 한 번에 이해할 수 있는가?
2. 개념의 이름보다 실제로 일어나는 일을 설명하고 있는가?
3. 같은 단어가 화면에 지나치게 반복되지 않는가?
4. 기술적으로 정확하지만 일상에서 쓰지 않는 표현이 남아 있지 않은가?
5. 버튼과 제목은 짧게 쓰고, 필요한 설명은 별도 도움말이나 접근성 속성으로 분리했는가?

피라미드라는 단어를 쓸 수 있었다면 간단히 해결될 부분도 많았지만, 실제 사용자에게 맞는 언어를 새로 설계하는 과정 자체가 앱 개발의 중요한 일부라는 점을 배웠다.
